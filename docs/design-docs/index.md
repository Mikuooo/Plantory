# Design Documents

Use a design document for a non-trivial change that crosses runtime, storage,
schema, package, service, or release boundaries.

Each document records:

- problem and source facts;
- contracts and responsibility boundaries;
- failure, compatibility, rollout, and rollback behavior;
- verification and evidence requirements;
- status: proposed, approved, implemented, or superseded.
